SPHEREx-Lens · machine-learning report · versions 1 to 18 · 13–25 Nov 2026

How the SPHEREx-Lens real/bogus model got from v1 to v18

One document for the whole story: what each version changed, what it scored, what went wrong, and what the data taught us. Written for teammates, judges and reviewers who were not in the sessions. Numbers come from the saved results files. Where an early version left no record, the report says so.

The short version

SPHEREx-Lens compares two infrared views of the same sky and flags anything that changed. The machine-learning (ML) score ranks those flags: how likely each one is a real change (a moving asteroid, a star changing brightness) rather than an instrument glitch. It never overrides the rule-based KNOWN/CANDIDATE verdict.

Versions 1–16 improved the algorithm and ended stuck: real variable stars were caught only 23% of the time. Versions 17–18 switched to improving the data, and that is what worked. Real variable-star ranking went from AUC 0.69 to 0.99, and real asteroid recall at an equal false-alarm rate went from 66% to 97%. The biggest lessons were about labels, not models: three times, a model scored well by learning how the labels were made rather than what the sky looked like.

2. Versions 1–16: improving the algorithm

v1 · the production baseline (rb-2026.11.13-1)

  • Model: one gradient-boosted tree model (HistGradientBoosting) on 22 numbers per detection, with isotonic calibration.
  • Data: 12,150 labelled detections from 18 patches. 6,519 "real" were almost all injected synthetic sources; 5,631 "bogus" were half-split null tests and masked pixels.
  • Held-out score: precision 0.957, recall 0.930. This looked excellent.
  • Problems found later:
    • Movers were all dipoles and almost no bogus examples were, so "is it a dipole?" alone looked like perfect skill (dipoles: 100%).
    • The "mask" bogus label was defined by a feature (masked_frac).
    • 6 of the 22 features were always empty.
    This was the first shortcut.

v2 · four approaches compared

  • Trees tuned with Optuna (approach A), a CNN on the 4-layer image stamp on the GPU (B), a hybrid (C), and ensembles and stacking (D).
  • A leak test checked whether the model still works on examples made in a different way. It showed the models leaned on how each example was made.
  • No saved score table survives for v2. Its role was to pick the direction, which was trees plus a CNN.

v3–v4 · more kinds of examples, the first real-sky exam

  • Added cross-provenance examples (real sources in null-type image pairs, bogus dipoles in real pairs) and star-anchored brightness changes.
  • LightGBM + CNN (3 seeds), isotonic calibration, and the first real-sky exam: real catalogued variables the pipeline detected.

v5–v6 · real-sky labels, honest testing

  • Real-sky labels entered training. Every real-sky number is now leave-patches-out.
  • The targets were set here: real caught > 80%, steady false alarms < 5%, simulated glitches < 5%, calibration error < 10%.

v7–v9 · two stages: simulation experts and a real-sky judge

  • Stage 1: experts trained only on simulations (trees; plus a CNN in v9). Stage 2: a small judge that learns from real sky, given the experts' opinions.
  • Fully nested, so no opinion ever came from a model that saw that row.
  • v9 on the first answer key: 62% of variables caught, 10.8% glitches passed, calibration error 9.7%.

Why the variable score "fell" from 81% to 36%: v9–v11 had learned to recognise artefacts that the early answer key wrongly called variables. Each correction to the key made the exam smaller and more honest, and the score dropped to what the data really supported. This was the second shortcut.

v15–v16 · two pipeline bugs found, the last algorithm-era model

  • Bug 1: wavelength mismatch. The pipeline compared each star at different wavelengths in the two epochs, so a star's colour looked like a brightness change (4–16% per detector). Matched-wavelength images brought each field's zero point to 1.00 ± 0.01.
  • Bug 2: asteroids erased. SPHEREx flags a moving asteroid's pixels as "outlier", and the co-add masked them. Without that mask, the asteroid was found in 64 of 67 fields instead of 14 of 40.
  • v16 results (answer key v6): 23% of real variables (15/65), 3.0% glitches passed, 1.9% steady false alarms, calibration error 6.2%, and real asteroids 58/65 (59/65 in the website version without the CNN).
  • v16 was built into the website code as an optional model, off by default. The fixes (commit ac8918b) were never pushed.
Where v16 left things: a good glitch filter and asteroid finder, but variable stars stuck near 23% whatever the algorithm did. The 23 Nov audit asked why, and found the answer in the data.

3. Version 17: the data-centric turn

The v16 data audit found

  • Only 65 real variable labels, and 30 of 41 patches had none. Yet the same patches hold about 1,010 large-amplitude catalogued variables. The label rules threw away about 95% of them.
  • The simulations looked unlike the real sky (a classifier separated them at AUC 0.88). Each simulator made only one class, so the model could learn "which simulator made this".
  • 22 of 42 patches had just two visits.
  • The asteroid "pass" (58/65) had a 95% range of 79–95%, so it wasn't proven.

What v17 did

  • v17a tested algorithm fixes on the old data: three experts (kept), real-sky-likeness weighting, fake PSF failures (dropped), per-class calibration. Variables stayed at about 26%, because the labels were the same.
  • Track 2 rebuilt the variable answer key honestly. It found that v16's noise estimate marked 40–55% of ordinary faint stars as "changed", so many old labels were noise. The new key had 35 real changes.
  • v17b trained on the new key: ranking AUC 0.69 → 0.91 with the same algorithm. Adding a direct brightness measurement caught 30 of 35.
  • Track 3 built the first large real asteroid exam: 276 asteroids and 2,137 steady stars in 845 new fields. It showed real-sky weighting hurt asteroids, so v17 became two heads without it.

4. Version 18: better data from new sources

The v17 audit found

  • Variable positives were 89% red giants, and the pipeline detected only 25% of real measured changes.
  • The asteroid model had never seen a real asteroid in training. Its simulations came from a different observing mode (AUC 0.997 apart).
  • Every glitch label was simulated, though the SPHEREx images carry their own quality flags.

Third shortcut, caught and fixed: the first v18 asteroid model learned "no star here and no flags means asteroid", because that is how the labels were defined. It flagged 6.8 unexplained detections per field. Training on detections already checked and found to hold no known asteroid fixed it. Lesson: set thresholds on realistic negatives (unexplained detections), not on easy ones (steady stars).

6. v18 on the website (branch ml-v18)

  • Base: GitHub main (teammates' latest UI and slides), plus the validity fixes from ac8918b.
  • Default ML model: v18. The website stacks all six detectors per epoch, so it serves v18's co-add model, the one trained on that kind of image. The single-exposure asteroid model waits for a future single-exposure mover mode, because serving it on co-adds would repeat the "different data" problem.
  • Tiers: "candidate" at score ≥ 0.5 (about 2% of steady stars flagged) and "needs review" at 0.2–0.5 (up to 5%). The site shows "needs review" on those rows.
  • No LightGBM on the website: the trees ship as plain arrays, 1.2 MB. Scores match training exactly (difference 0.0), and the website's feature code matches the training code exactly (difference 0.0 on 932 real rows).
  • Tests: 276 pass, including new parity tests for features, scores, tiers, the default model, the model page and the metrics block.
  • One source of truth: ml/models/LATEST.json names v18, so scoring, the model page (/api/model, text from ml/MODEL_CARD.md) and the metrics page all describe the same model. The metrics page shows v18's real-sky precision 0.970, recall 0.922 and PR-AUC 0.990, and the metrics regression gate passes.
  • v16 retired: removed from the website. Its feature code lives on as spherexlens/ml/imagefeat.py, because v18 uses it. The original v1 model can still be selected with SPHEREX_ML_MODEL=v1. Each website model has a JSON model card next to it in ml/models/.
  • Still experimental: the score only ranks, and the site says so.

7. Lessons

  1. Check the labels before the model. Three times a high score came from how labels were made: dipoles in v1, artefacts as "variables" in v9–v11, and "no star = asteroid" in v18.
  2. Better data beat better algorithms. The same recipe went from AUC 0.69 to 0.99 on variables when the labels improved.
  3. Test where you'll use it. Same observing mode, same pipeline, unseen patches, and in future, unseen time.
  4. Compare at equal false alarms. v17's "65% vs 47%" asteroid gain vanished at equal false-alarm rates. v18's gain held.
  5. Report ranges, not single numbers. 58/65 sounds like 89% but means 79–95%.
  6. Measurement beats guessing for variability. A direct, wavelength-matched brightness measurement ranks almost as well as the ML (AUC 0.987 vs 0.989). The ML's job is to catch what the noisy measurement misses.
  7. Independent eyes are a data source. Without human review, every "real" is our own rule's opinion.
